# Where do streamed bitmap frames begin to skip on stock Arthur?

Run the same synthetic frame workload 60 times at each plotting load. Increase the number of bitmap plots only after the 60th completed update. The result is a curve of missed VBlanks versus plots per frame while the eZ80 streams rows from SD through stock Arthur's synchronous UART0. At a nominal 60 Hz, 60 load levels take about a minute when every update fits. The sweep naturally runs longer once frames start slipping.

## Self-contained workload

- FRAME-001 [ ] Generate a deterministic SD file before timing, open it once, and prime a 1 KiB read buffer. A 60-level sweep at 256 bytes per update needs 921,600 payload bytes. Use a fixed 72-byte header before the payload to reproduce the original Earth file's sector offset. Generate one small RGBA2222 plot tile in setup. Record its dimensions, opacity pattern, and the VDP and MOS identities. The fixture has no Nurples asset or music dependency.
- FRAME-002 [ ] In mode 20 on stock Bistromathics, submit one 256-byte row per update directly from the current read buffer using the Earth-style 11-byte adjustment header, and plot that row. Add a fixed number of identical tile plot commands at deterministic on-screen positions. Keep tile size, clipping, command mix and payload cadence fixed. Use two 1 KiB eZ80 buffers so a prefetch can fill the next block while unread rows remain in the current block. Allocate the VDP buffers once and clear them after the measured sweep.
- FRAME-003 [ ] Start at zero extra tile plots. Use one additional tile plot per update at each successive level as the initial sweep. Keep each level for 60 completed updates. The streaming workload then consumes exactly 15 four-row blocks per level. Preserve the normal refill cadence across level boundaries and account for the primed block and final drain. Record actual refills. If the first sweep never crosses the deadline, report the highest tested passing load and increase the range on the next run.
- FRAME-004 [ ] At frame start claim the latest delivered VBlank. Submit the scheduled drawing and row data. At the end of the frame, when the next block is due and there is still time before the next edge, perform one synchronous SD refill. If a refill must happen before its first row can be submitted, mark it as forced. Recheck the same claimed edge after a read. Start the next update as soon as an edge is pending; wait only while the edge count is unchanged. Coalesce excess edges, with no catch-up burst.

## Readout

Use a bounded in-RAM record per load level and emit the table after the sweep. Account for elapsed edges from each update start through the next start, including the last measured update. Decode Arthur's clock increment into delivered VBlanks and handle wrap. One elapsed edge is on pace; two elapsed edges mean one skipped. Attribute each interval to the load that produced it. Record the number of updates that skipped, total skipped edges, longest gap, and whether the first skip coincided with a refill. Time synchronous row submission and SD refill separately with a calibrated eZ80 timer, retaining counts and maxima. A UART submission time ends when foreground regains control. Perform a known-pixel or ordered completion check after timing to verify the stream arrived.

Report the first level with any skip and its count out of 60. Preserve the counts at adjacent levels so a single SD stall is distinguishable from a sustained rise. If attribution matters, repeat the same ramp with prefilled RAM supplying the row data, preserving the identical synchronous uploads and plots. That measures how much the SD refill changes the onset. The initial sweep stands on its own.

The historical [Earth dispatch review](/Agon/mystuff/nurples/docs/tasks/EARTH-001/vblank-dispatch-review.md) supplies the four-row fetch and single-row send cadence. The [Extender Legacy SD fixture](/Agon/mystuff/agon-extender-legacy/agm/agon/sdbench/src/main.c) supplies a reusable sequential-read loop. This plan measures the load boundary for the synthetic command mix. Mapping a Nurples scene onto the curve requires its actual command mix and foreground cost.
